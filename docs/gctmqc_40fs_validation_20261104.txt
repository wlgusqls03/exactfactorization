검증 범위
---------
저자 G-CTMQC b7a2a6d95656e4e0535e744b102670d85b07fb88의 별도 adapter 경로다.
기존 MCEF, TDSE, Python CTMQC 전파기와 사용자의 이전 결과는 변경하지 않았다.
2026 두-state PEN 모델, DSE OFF, g=0.01, seed=2026, nesteps=1,
DoubleIntercept=false, 기본 M_parameter=100을 사용했다.
M_parameter는 quantum-momentum 거리 제한 계수이지 질량/광자 coupling이 아니다.
EL: upper local CBO + classical photon Wigner sample.
POL: bare S1 x photon vacuum, photon Fock n=0,1.
서로 초기 준비가 완전히 같지 않으며, QD도 유한 Fock reference다.
논문 photon-grid QD 및 논문의 정확한 소스/입력 재현 인증은 아니다.

1. 실제 수정한 결함
------------------
(1) native/coeff, native/trajectories를 실행 전에 만들지 않던 문제.
    저자 Fortran이 OPEN 오류 후 fort.128에 쓰며 계속 실행할 수 있었다.
    이제 폴더를 생성하고 OPEN 오류/fort.*/누락 프레임을 검출한다.
    각 native text와 binary의 X,P,surface,conditional energy,ensemble energy,
    photon number,density-matrix trace를 독립적으로 대조한다.

(2) 공개 소스 main.f90에서 비주기 periodic_in/period가 미초기화였다.
    TRUE인 좌표만 대입하고 나머지를 지정하지 않아 잘못된 분기 가능성이 있었다.
    False/0 초기화 후 기존 periodic 설정을 적용한다. 실제 runtime flags,
    M_parameter, DoubleIntercept도 로그에서 확인한다.
    열린 경계 Q cutoff가 함의하는 k_ij 상한도 모든 snapshot에서 검사한다.

(3) tools.f90의 coup_so가 SPIN_DIA=false일 때 미초기화였다.
    coefficients_evolution.f90 cdot는 이를 무조건 읽으므로 결과가 heap 내용에
    의존했다. 비활성 SOC를 0으로 명시 초기화한다.

(4) RPE 파일에 미초기화 Vdiadiag 뒷열을 출력하던 문제.
    이 쓰레기 값 열을 제외하고 물리적으로 정의된 앞 열만 유지한다.

전파식/Verlet/RK coefficient scheme/quantum-momentum 식/force-history threshold는
교체하지 않았다. 단, 미초기화 메모리를 읽던 동작이 바뀌므로 기존 binary로
계산한 결과와 다를 수 있다. 기존 자료를 재렌더만 해서는 수정되지 않는다.
특정 공개 소스 경로의 결함을 확인한 것이지, 논문 결과 전체가 틀렸다는 뜻은 아니다.

-------------------------------

dt005_n128:  비단열/Rabi x on/off x EL/POL = 8 cases, dt=.05 a.u.
dt0025_n128: 같은 8 cases, dt=.025 a.u.

N을 바꾸면 같은 seed라도 동일한 paired ensemble이 아니다. 이 검사는 추가
장시간 stress test이며, Ntraj 수렴/여러 seed에 대한 통계 검증을 대신하지 않는다.

각 case 아래 config.json, author_settings.json, status.json, validation.json,
output_validation.json, observables.json, model_check/, adapter_frames/, native/.
40 fs endpoint는 ceil(step)로 정하므로 dt=.025에서 실제 마지막 시각은
40.00048538766608 fs다. 저장 간격은 10 a.u.=0.24188843265857 fs.
binary 167프레임(0과 endpoint 포함), native는 dump 배수 166프레임이다.
native 마지막 39.911591... fs를 binary 누락으로 해석하면 안 된다.

128개, dt=.025에서 측정한 최대 정규화 전 norm 오차 및 최대 |E(t)-E(0)|:
  case                    raw norm error    energy change (Ha)
  nonadiabatic/off EL      3.96585e-5        1.02506e-2
  nonadiabatic/off POL     2.22752e-6        1.48497e-4
  nonadiabatic/on  EL      3.36081e-4        2.43215e-2
  nonadiabatic/on  POL     3.15034e-5        1.21524e-2
  rabi/off EL             1.56231e-7        4.64994e-5
  rabi/off POL            1.76090e-10       2.99815e-10
  rabi/on  EL             1.48063e-6        8.59724e-6
  rabi/on  POL            3.25057e-9        1.49485e-9

norm=1은 저자가 매 전자 step마다 정규화한 결과다. 별도로 기록하는 raw norm은
두 snapshot 사이 모든 step의 최대 오차이며 순간 snapshot 오차가 아니다.
에너지 변화는 CTMQC 방법 자체의 비보존성과 적분 오차를 모두 포함할 수 있다.
따라서 energy drift만으로 코드 버그라고 단정하지 않는다.

dt=.05 -> .025: Rabi에서 photon-number 최대 차이는 EL <=4.63e-4,
POL <=3.36e-7이었다. 비단열의 경우 population/에너지 변화 민감도가 남는다.
dt=.025 -> .0125, 비단열/on:
  EL:  max |delta P_BO|=.02955, max |delta Nph|=.01386.
  POL: max |delta P_BO|=.02941, max |delta Nph|=.00650.
  최대 에너지 변화는 EL .02887 Ha, POL .01231 Ha로 작아지지 않았다.
M=100 -> 50 역시 이를 해결하지 못했다(EL energy .01771, POL .01353 Ha).
이 parameter를 바꾼 결과를 기본 production이나 논문값으로 몰래 채택하지 않았다.

메모리 재현성:
  MALLOC_PERTURB_=0/165, 8개 model/resonance/view의 짧은 검사를 통과했다.
  더 나아가 비단열/on EL/POL의 40 fs 계산을 allocator perturbation으로
  재실행한 결과, 각각 167개의 전체 binary snapshot이 모두 byte-identical.
  따라서 이 검사에서 초기화 결함 수정의 효과와 남은 dt/M 민감도를 구분했다.

1000개 장시간 검사도 두 경우 모두 40.000485 fs까지 완료했다:
  view   max raw norm error   max |delta E| (Ha)   전파 시간(로컬)
  EL     1.20951e-3           4.48333e-2           1349.6초 (22.5분)
  POL    1.19078e-4           1.54603e-2           1272.1초 (21.2분)
두 경우를 병렬로 실행했다. 도중 다른 검증/렌더 작업도 함께 수행했으므로
이것은 순수 단독 core benchmark가 아니다. 서버 속도 보장은 아니다.
N을 늘린 것만으로 비단열 장시간 오차가 해결되지는 않았다.

수정본 총 24개 40 fs 실행은 모두 binary/native 출력 검사를 통과했다.
최대 surface/독립 MF-force 불일치 <=2.91e-15, Q-cutoff 상한 위반 0.
native text와 binary의 위치/운동량 차이는 <=5e-7, photon number <=5e-9로
각각 Fortran의 소수 6자리/8자리 출력 반올림 범위다.
모든 프레임이 finite였고, 출력 정상 여부와 수치적 수렴 여부를 혼동하지 않았다.
최종 통합 판정은 ROOT/health_all.json에 저장했다.

비용/용량:
  128개 dt=.025의 40fs: 전파 약58-122초/case (동시 작업이 있었음).
  1000개 dt=.025의 40fs EL+POL: 약210 MiB, 그림 포함, full wave 저장 없음.
  이를 8 cases로 단순 외삽하면 약0.8-1.0 GiB + 동영상/여유 용량.
  두 case 병렬 기준 전파 약90분, 한 case씩이면 약3시간 규모의 추정이다.
  실제 서버에서는 1fs pilot 속도를 먼저 측정하고 렌더 시간은 추가한다.
  이번 최종 검증 ROOT는 약0.55 GiB; 새 build는 별도 약1.6 GiB.
  수정 전 진단/구 build는 별도로 보존했으며 자동 삭제하지 않았다.

export GCTMQC_PREFIX=/home/hbji/exactfactorization/results/_dependencies/gctmqc_linalg

먼저 로컬에서 안정성이 확인된 Rabi의 40 fs 서버 비교:
python -m multi_component_exact_factorization.pen_gctmqc_2026.workflow \
  --build results/_dependencies/gctmqc_b7a2_initfix_v3 \
  --out results/20261104/gctmqc_rabi_40fs_server_v3 \
  --model rabi --resonance both --perspective both --case strong \
  --ntraj 1000 --dt 0.025 --end-fs 40 \
  --every-fs 0.24188843265857 --jobs 1 --threads 1 --movies

공유 서버에서 jobs=1이면 한 case씩 실행한다. 허용된 자원이 있으면 jobs=2.
그림과 영상은 자동 생성한다. 기존 source tree는 재사용하지 않고 archive만
재사용한다. 안전하게 새 경로에 빌드해야 하며 old restart도 사용하지 않는다.

완료/품질 판정:
python -m multi_component_exact_factorization.pen_gctmqc_2026.health \
