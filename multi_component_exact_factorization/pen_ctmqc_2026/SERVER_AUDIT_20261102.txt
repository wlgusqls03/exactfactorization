2. 발견하여 수정한 비교 문제
---------------------------
기존 비교 JSON의 source_ctmqc는 ctmqc_paper_server_v1이었다.
실제 pilot_server_v1과 경로가 달랐다. 9개 비교 group 모두 methods=['qd']였다.
따라서 기존 40 fs 비교 그림은 QD-only이며 CTMQC 비교 결과로 사용하면 안 된다.
원자료/기존 그림은 삭제하거나 덮어쓰지 않았다.

compare.py는 이제 기본적으로 QD+EL+POL이 모두 있는 group만 그린다.
없는 root 또는 모든 group 불일치는 그림 생성 전 실패한다.
의도한 부분 비교만 --allow-partial로 허용하고 PARTIAL 표기를 넣는다.
--require-through-fs 40은 모든 포함된 방법이 실제로 40 fs까지 있어야 허용한다.
--t-max-fs는 그림의 상한이며 짧은 자료를 40 fs까지 연장하지 않는다.
QD/EL/POL의 색뿐 아니라 실선/파선/일점쇄선을 다르게 하여 겹침도 확인할 수 있다.
EL 초기 photon-number의 Wigner sampling standard error도 표시한다.

4. 서버 실행: 현재 1,000개 궤적 유지, 8개 모두 40 fs까지

로컬 수정 commit을 GitHub에 push한 뒤 서버에서:

cd /home/hbji/exactfactorization

conda activate MCEF
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
export MPLCONFIGDIR=/tmp/pen-ctmqc-2026-mpl

# 먼저 저장 파일/checkpoint 점검. 입력에는 쓰지 않는다.
python -m multi_component_exact_factorization.pen_ctmqc_2026.audit \
  --root results/20261102/ctmqc_pilot_server_v1 \
  --out results/20261102/ctmqc_server_audit_v1/before_resume.json --target-fs 40

# 권장 중간 점검: 5 fs까지만 전파, 이 단계에서는 rendering 생략.
bash multi_component_exact_factorization/pen_ctmqc_2026/run_server.sh run \
  results/20261102/ctmqc_pilot_server_v1 \
  --model all --resonance both --perspective both --case strong --dse off \
  --ntraj 1000 --seed 2026 --dt 0.1 --every-fs 0.1 --initial paper \
  --end-fs 5 --resume --jobs 2 --no-render

python -m multi_component_exact_factorization.pen_ctmqc_2026.audit \
  --root results/20261102/ctmqc_pilot_server_v1 \
  --out results/20261102/ctmqc_server_audit_v1/after_5fs.json --target-fs 40

# after_5fs.json의 energy/guard/norm 및 실패 여부를 보고 다음 단계로 진행.
# 파일검사 PASS가 에너지/표본 수렴을 대신하지 않는다.
# 1 fs checkpoint에서 바로 40 fs로 갈 때도 아래 명령은 동일하다.
bash multi_component_exact_factorization/pen_ctmqc_2026/run_server.sh run \
  results/20261102/ctmqc_pilot_server_v1 \
  --model all --resonance both --perspective both --case strong --dse off \
  --ntraj 1000 --seed 2026 --dt 0.1 --every-fs 0.1 --initial paper \
  --end-fs 40 --resume --jobs 2 --movie-stride 2 --png-every-fs 5 \
  --tdse-root results/20261030/pen2026_paper_v1

# 위 계산은 각 케이스의 plots/에 CT 영상/그림을 자동으로 다시 만든다.
# --movie-stride 2는 약 0.2 fs마다 movie frame; 저장/전파 간격은 바꾸지 않는다.

# Ntraj=10000 또는 dt/seed/bandwidth/guard 변경은 같은 checkpoint로 이어갈 수 없다.

# 40 fs 세 방법 비교. 기존 잘못된 QD-only 폴더와 분리한다.

5. 실제 서버 pilot 기반 시간/용량 외삽 (측정된 40 fs 결과가 아님)
-------------------------------------------------------------
서버 1 fs propagation: EL 약 8초/케이스, POL 약 18–20초/케이스.
1->40 fs 추가 전파 외삽: EL 5.2–5.3분/케이스, POL 11.7–12.8분/케이스.
8개 합산 약 71 CPU-worker 분. jobs=2 이상적 약 35분이나 CPU 경합/후반
quantum-momentum 처리 비용에 따라 늘어날 수 있다.

중요: 위 시간에는 그림/영상이 없다. 서버 기존 render는 12 frame에 약 30초였다.
40 fs/0.1 fs 저장, movie-stride=2이면 약 202 movie frame/케이스이므로,
8개 자체 render도 약 1시간 이상의 worker 시간이 추가될 수 있다.
여기에 별도 세 방법 비교 생성까지 포함해 jobs=2 기준 약 1.5–2.5시간을
우선 작업창으로 잡는다. 실제 서버 부하 및 해상도에 따라 달라지는 예상이다.

8개 추가 trajectory frame: 비압축 배열 약 0.411 GiB (헤더 제외),
초기 압축률 단순 외삽 약 0.332 GiB. 원자료만으로 수십 GB가 필요하지 않다.
초기보다 압축률이 나빠질 수 있다. JSON/restart/PNG/MP4 및 비교 결과를 포함해
2–3 GiB 여유를 권장한다. 오래된 비교 폴더는 이 작업에서 삭제하지 않았다.
--movie-stride 1이면 영상 생성량/시간이 증가한다. --no-render면 전파만 수행 가능.

6. 로컬에서 수행하지 않은 일
---------------------------
8개 40 fs CTMQC production은 로컬에서 수행하지 않았다.
기존 서버 입력을 읽어 검사/재렌더했고 회귀검사에는 아주 짧은 합성 run만 썼다.
실제 40 fs의 CT guard, 에너지 변화, sampling convergence, 논문 정량 재현은
서버의 장시간 결과와 추가 수렴 검사 후 판단해야 한다.
